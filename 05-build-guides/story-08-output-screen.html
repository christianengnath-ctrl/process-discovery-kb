08 — Sub-Component Map
4 tab views + 1 node component — data sources and render responsibilities
Component Reads Renders Notes
FlowchartView NODES, CLASS_COLOR Header row + legend, dot-grid .flow-canvas with SVG arrows + 6 FlowNode components, below-canvas "Selected step" card + "Coverage" card Canvas uses position:relative; nodes are absolutely positioned via x/y/w/h props
SipocView SIPOC_ROWS Header + sub, card (padding:0, overflow:hidden) containing .sipoc-table with 5 header columns + 5 data rows Table card has no padding; overflow:hidden clips border-radius correctly
SopView SOP_SECTIONS Header row with "7 sections" chip, content card (maxHeight:460, overflowY:auto) with doc heading block + 7 .sop-section divs Doc heading uses uppercase letterSpacing:0.1em for the sub line
TranscriptView TRANSCRIPT_TURNS Header row with "Complete" chip (green dot), content card (maxHeight:480, overflowY:auto) with 11 .transcript-turn rows Timmy → .timmy (blue), Interviewee → .interviewee (green-soft); classes set in index.css
FlowNode CLASS_COLOR[kind] Absolutely-positioned node card: left stripe, kind label (colored), step name, footer (actor left + conf% right) Props: name, actor, kind, conf, x, y, w, h — all from NODES array

09 — Constraints
Hard "must NOT be present" rules
No loading per tab No error per tab No download button No regeneration button No fullscreen / zoom No editable fields No real-time generation No tab-level loading spinner No per-tab error state No clipboard success toast

All output data is hardcoded demo constants at the top of Outputs.jsx. There is no async state, no fetching, and no generation trigger. Tab switching is always instant.

canStart Logic

When "Start interview" is enabled vs disabled

Simple derivation: at least one goal with non-empty trimmed text.

// canStart computation
const canStart = goals.some(g => g.text.trim());

// Button disabled when
<button disabled={!canStart}>

// Example states:
goals = [] → canStart = false → disabled
goals = [{text: ''}] → canStart = false → disabled
goals = [{text: ' '}] → canStart = false → disabled
goals = [{text: 'abc'}] → canStart = true → enabled
Button enabled state
Constraints

Do NOT build these

Explicitly out of scope for this story.

NOLLM API call — goals are pure JS, no model involved
NOAsync operations — all state changes are synchronous
NOConfirmation dialog on remove — ✕ removes immediately
NODrag-to-reorder — goals stay in insertion order
NOGoal cap error message — add trigger simply hides at 5
NOUndo for removed goals
NOLoading state — store is synchronous
NO"covered" toggle on this screen — managed by interview screen

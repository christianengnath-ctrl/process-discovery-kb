Component Anatomy

Mode card anatomy

Each mode card is a <button> with 3 zones. The selected card has class mode-card selected.

Zone map · Flex row · icon | text | radio
Zone Class Notes
Icon .mode-card-icon Emoji, left-aligned. Box sizing via CSS.

Radio .mode-radio Empty circle when not selected. Add .checked for filled dot.
Selected .mode-card.selected Bold border (#333, 2px). Darker fill (#ececec). Filled radio.
Summary Chips

Chips · Row, flexWrap, justifyContent center · mt-32 · row gap-8
handleStart Flow

Button click → navigation sequence

Async function with a mandatory 400ms delay. Do not remove the delay — it ensures Zustand write flushes before LiveInterview mounts.

1setStarting(true)
   // disables button, changes label to "◌ Starting…"

2updateProject(id, {
    interviewMode: mode,
    status: 'interviewing'
})

3await new Promise(r => setTimeout(r, 400))
   // 400ms — intentional, do not remove

4navigate(`/projects/${"{id}"}/live`)
handleStart · Yellow = 400ms intentional delay
Constraints

Do NOT build these

Explicitly out of scope for this story.

NOStep indicator — centred layout, no wizard progress bar
NOURL validation — no Google Meet URL input or external link field
NORecall.ai — no meeting bot or recording service integration
NOLoading spinner on mount — store is synchronous, guard redirects on missing project
NOError state — missing project handled by navigate('/') guard only
NOConfirmation dialog — clicking Start fires immediately, no "are you sure?"
NOMode count badge or indicator in chips

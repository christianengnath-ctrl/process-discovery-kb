Story 02 · Process Discovery

Create Project

Screen CreateProject
Route /new
File src/screens/CreateProject.jsx
Exists — verify & fix gaps
Wireframe A — Empty form

Initial state

All three fields are blank. The "Create project →" button is disabled — grayed out and non-interactive. The user must fill all three fields before they can proceed.

Wireframe B — Filled form

Submit-ready state

All three fields contain non-whitespace text. canSubmit evaluates to truthy. The "Create project →" button activates — solid fill, full opacity, clickable.

Navigation Flow

Where each action goes

The form is a single screen. Submit calls createProject() synchronously, gets back the new UUID, then navigates. Back navigates to / without touching the store.

Field Anatomy

Input field structure

All three fields use the same pattern: input-label → input → optional input-helper. Field 3 (goal) is the only one with helper text.

Submit Guard Logic

Button state transitions

The submit guard is a single derived boolean. No loading state, no error state. The button either allows submission or it does not.

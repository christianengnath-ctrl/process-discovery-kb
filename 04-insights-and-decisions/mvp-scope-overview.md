# MVP Scope Overview — Process Discovery Agent

*Updated: May 21 · Reflects all scope decisions post-kickoff*

---

## Smallest MVP — end-to-end nucleus

Nine phases, mapped to what's in vs. deferred:

---

### Phase 1 — Campaign setup
**In nucleus. ~1h to build.**

User lands on the project list. Creates a new project:
- Client name
- Process name (e.g. "Refund processing")
- One-line goal ("We need to understand how refund requests are handled end to end")

No dates, no team members, no complexity. The refund processing project is pre-seeded so the demo never starts blank.

---

### Phase 2 — Context integration
**In nucleus. ~1-2h.**

After project creation, a single "Add context" step. User pastes:
- Existing process docs (Notion page text, email thread, SOP PDF content)
- Or skips it if there's nothing

Stored as the project's `context_blob` — plain text, locally. Timmy reads it before generating his first question. This is what makes him sound like he already knows the client rather than starting cold.

---

### Phase 3 — Define what needs to be explored
**In nucleus, but simplified. ~1h.**

After context upload, Timmy (or a setup screen) proposes 3-5 suggested exploration goals derived from the context. User can edit or approve them. Example:
- "Understand who initiates the refund request"
- "Map the approval chain for amounts over $500"
- "Identify what systems are involved"

These become Timmy's internal agenda — the topics he must cover before closing the interview. This is what separates a structured interview from a random conversation.

---

### Phase 4 — AI interview (voice in Google Meet)
**In nucleus. Core demo moment. ~3-4h for Sara + Syed.**

Voice-based. Timmy joins the Google Meet as a bot via Recall.ai and speaks directly in the call. His voice is generated by ElevenLabs TTS. During the interview, the Timmy web app shows an avatar image and a session status indicator (speaking / listening) — no live flowchart during the call. The flowchart builds in the background and is shown only on the output screen after the session ends.

Timmy's flow:
1. Introduces himself, explains the session (~1 turn)
2. Open question: "Walk me through what happens when a refund request comes in"
3. Follows up dynamically based on the answer
4. Checks off exploration goals as they're covered
5. Probes decision points and gaps when a step is mentioned but not explained
6. Closes when all goals are covered OR interviewee says done

Each turn: interviewee speaks → Recall.ai delivers transcript → Timmy loop runs → KB updates in background → Timmy responds with voice.

**Key constraint: lock to the refund processing scenario. Pre-seed the context and goals. Do not demo a blank-slate interview.**

**Fallback (if Recall.ai not working by Thu 15:00):** Timmy as a sidebar app — voice plays through speakers, interviewee stays on Meet. Core loop is identical, only audio plumbing changes.

---

### Phase 5 — Information intake and processing
**In nucleus. Runs silently per turn. ~2-3h.**

After each interviewee answer, the system runs a lightweight extraction:
- What process step was just described?
- Who is the actor?
- Is there a decision point?
- What system is involved?
- Confidence: clearly stated or inferred?

This feeds directly into the flowchart. Each extracted element becomes a node or edge. This is the "intelligent AI in the back" — it must not be skipped or faked for the demo.

Implementation: one LLM call per turn with a structured JSON output schema. Fast, cheap, reliable.

---

### Phase 6 — Knowledge base building
**Simplified for nucleus. Single-session only.**

For Friday: the KB is the accumulated structured extractions from the current session stored in memory or a local JSON file. No vector DB, no embeddings, no cross-session persistence.

What it enables:
- Timmy references earlier answers ("You mentioned the AP clerk validates the invoice — who do they escalate to if the amount is over $500?")
- Gap detection: which exploration goals still have low confidence?
- The flowchart reflects cumulative understanding, not just the last answer

Multi-session memory → post-Friday roadmap Week 1.

---

### Phase 7 — Multi-interview contextualization
**Confirmed out of scope.**

The "10 interviews, then 10 more focused on gaps" loop. Requires persistent KB, session history, and a gap-driven question generator. Named in the Friday demo as a Week 1 roadmap item.

---

### Phase 8 — Orchestration (the Timmy loop)
**In nucleus. Runs per turn, no extra build time beyond the loop itself.**

Simple state machine — four states:
1. `setup` — project created, context added, goals defined
2. `interviewing` — active session, Timmy asking, flowchart updating
3. `processing` — session ended, generating outputs
4. `complete` — all outputs ready to view

Per-turn loop inside the `interviewing` state:
```
Recall.ai utterance-end → transcript
  → extraction call → structured JSON
  → KB update → local array
  → goal tracker → coverage status
  → question generator → next question
  → ElevenLabs TTS → audio
  → Recall.ai audio injection → Timmy speaks
  → flowchart update → new node emitted to UI
```

No background jobs, no queue, no async workers. One user, one thread, synchronous calls.

---

### Phase 9 — Output generation
**In nucleus. ~3-4h for Lucas in Stream 3.**

Three outputs, generated when the user clicks "Generate outputs":

**A. SIPOC table**

| Suppliers | Inputs | Process Steps | Outputs | Customers |
|---|---|---|---|---|
| Derived from actors/systems in KB | Trigger + inputs | Numbered steps with classification tags | Deliverables | End recipients |

**B. Labeled process flowchart**
- Each node gets a step classification: `Deterministic` / `Agentic` / `RPA Bridge`
- Confidence score shown per node
- Rendered in the same flowchart view that built during the interview

**C. Standard SOP document (text)**
1. Purpose
2. Scope
3. Roles & Responsibilities
4. Process Steps (numbered, decision points inline)
5. Exceptions & Edge Cases
6. Systems Used
7. Approvals

All three generated from the KB accumulated during the session. One additional LLM call for the SOP on top of what Stream 3 already builds for A and B. Adds ~1h to Lucas's scope.
